# SplatForge 0.0.1a1 — source preview

Released: 2026-10-15.

**Reusable operators and a modular framework for Gaussian Splatting and 3D
reconstruction research.**

SplatForge is building a toolbox for taking components from reconstruction
papers and making them easier to inspect, test, and reuse. The goal is to
bring an idea from one method into another and evaluate it within a shared
research workflow.

We start with geometry-oriented Gaussian Splatting. The intended next stage
is a usable framework and operator library; the longer-term direction includes
more GS methods, selected MVS components, and geometry processing.

This release is the first public code preview of that direction. It makes the
prototype source available for continued development. APIs and abstractions
are still evolving.

The source contains an operator runtime, mathematical building blocks, method
recipes, and a shared application workflow. The method prototypes help test
and refine the library's abstractions.

## Included

- Versioned operator runtime and explicit provider/capability contracts.
- Gaussian geometry, compositing, ambiguity, opacity-field, and ZNCC operators.
- Experimental RaDe-GS, AmbiSuR, and GOF Studio recipes.
- Shared training, checkpoint resume, evaluation, mesh export, and local viewer.
- A separately installed Unbiased Surfel / PGSR-style auxiliary package in the
  full repository source archive, independent of the Studio method registry.

## Source snapshot

The complete public source ZIP includes the main framework and the independent
companion. The [Git tag](https://github.com/KCBtheone/SplatForge/tree/v0.0.1a1)
identifies the original preview code. Ongoing source and documentation
development continues on `main`.

External renderers, datasets, model weights, private scan outputs, and local
operational records are excluded. Installable packages are secondary
conveniences alongside the source archive.

The public snapshot also omits local server orchestration utilities and tests
specific to those utilities. Operator, runtime, component, and synthetic
Studio integration tests are retained.

## Verification

The release verification record is published alongside the release assets.
It covers local CPU tests, source-distribution rebuilding, an installed-wheel
check, and an analytic demo. GPU builds and paper benchmark parity are not
established by these checks.

## Prototype status

Three Studio recipes are integrated and the companion remains independent.
Interfaces may change as the abstractions develop. Synthetic tests and CPU CI
exercise the implementation; real-scene quality, paper reproduction, and
accelerated backend performance require separate validation. Method differences
and optional dependencies are documented in the repository.

See the [roadmap](../ROADMAP.md) for the later operator-library and ecosystem
stages.
