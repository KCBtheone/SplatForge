# Surface Studio preview

Studio is the experimental application above SplatForge's operator runtime.
RaDe-GS, AmbiSuR, and GOF share data loading, a model/pipeline interface,
training, checkpoints, evaluation, exporters, and a local viewer.

## Commands

```bash
splatforge methods
splatforge config gof --output gof.yaml --data /path/to/scene
sf-train --config gof.yaml
sf-train --config gof.yaml --resume latest
sf-export --run outputs/run
sf-eval --run outputs/run
sf-viewer --run outputs/run --host 127.0.0.1 --port 8080
```

Training defaults to CUDA. Pass `--device cpu --backend torch` for a small CPU
experiment. Configuration overrides use `--set section.field=value`; unknown
fields fail explicitly. Use a new output directory for a new experiment and
`--resume latest` for an existing run. Resume restores optimizer, RNG, and
camera-sampling state; changing a method or loss requires a new experiment.

## Inputs

COLMAP input contains `images/` and `sparse/0/` (or `sparse/`). Binary and text
`PINHOLE` and `SIMPLE_PINHOLE` cameras are supported. Undistort other camera
models before using them. Images must match the camera dimensions. Optional
foreground masks go in `masks/`; RGBA alpha is also supported.

JSON scenes use `scene.json` or `transforms.json`, camera intrinsics,
per-frame poses, and initial points/colors. A minimal example is generated by
`splatforge demo --output demo-data`. Explicit `camera_convention="opencv"`
means camera-to-world matrices use OpenCV axes. Unannotated Blender-style
transforms use OpenGL axes and are converted.

AmbiSuR requires training-view depth priors in
`priors/<image-stem>.npz`, at original image resolution. Each file contains
camera-z `depth` in scene units; `normal` and `confidence` are optional.
Subdirectories are preserved. This preview does not automatically download
prior models. The optional DA3 adapter and recorded BASE configuration differ
from the paper's prior-model configuration.

## Methods and backend boundaries

| Recipe | Included mechanisms | Default backend / export |
| --- | --- | --- |
| `radegs` | Per-pixel plane depth, normals, L2 distortion, depth-normal consistency; optional multiview terms | Pinned gsplat port / TSDF |
| `ambisur` | Ray-color ambiguity, SH filtering, prior supervision, gradient-isolated geometry constraints | Torch / TSDF |
| `gof` | Ray-Gaussian response, L1 distortion, opacity field, tetrahedral extraction | Torch / GOF isosurface |

The RaDe-GS backend is an optional external dependency. Install it in a
dedicated CUDA environment after installing the required PyTorch build:

```bash
python -m pip install ninja jaxtyping rich
python -m pip install --no-deps --no-build-isolation \
  git+https://github.com/Mollylulu/gsplat_radegs.git@23b0f82551a938a05b5b99df06edf220b9305a51
```

The ordinary PyPI gsplat package does not satisfy this adapter's pinned API.
The reference `torch` backend can exercise all three recipes on small inputs.
`torch-batched`, `torch-compiled`, and the optional CUDA composite backend have
separate execution and toolchain requirements. They are explicit choices, and
unsupported configurations raise errors.

The `gsplat-radegs-stable-moments` variant explicitly uses float64 Cholesky
geometry with its own differentiable contract. It is not native backward
equivalence. Backend and recipe differences are recorded in
[`../../provenance/surface_methods.json`](../../provenance/surface_methods.json).

## Mesh and evaluation

The default adaptive TSDF uses a tetrahedral discretization. To use Open3D's
voxel TSDF, install `.[mesh]` and set `export.tsdf_backend=open3d`.
GOF exports an opacity-field isosurface. The synthetic demo can check that a
mesh is produced, but it cannot establish reconstruction quality.

`sf-eval --run outputs/run` evaluates saved image views. Geometry comparison
accepts `--prediction`, `--ground-truth`, `--threshold`, and an optional 4x4
`--alignment` matrix. These nearest-neighbor metrics do not automatically
apply DTU or Tanks and Temples benchmark protocols.

## Extension points

Python entry points register `splatforge.methods`, `splatforge.dataparsers`,
`splatforge.renderers`, and `splatforge.exporters`.
A method provides `default_config()` and `make_pipeline(config)`.
The pipeline owns representation state and optimizer groups; the trainer
handles the shared lifecycle. Operators and providers remain independently
usable through the core runtime.

## Evidence boundary

Synthetic forward/gradient tests, short training, exact checkpoint resume,
mesh export, and viewer checks exercise the implementation. They do not
establish author-code agreement, complete paper reproduction, real-scene
quality, or GPU performance. This preview does not distribute private scans,
experiment checkpoints, prior weights, or local server controllers.
